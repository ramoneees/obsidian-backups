# I Kept Rebuilding the Same Agent for Every Client. Then I Changed the Model.

**Thanh Pham** — a business-model insight, not a technical one.

## The old model
For the first year of doing AI implementation, Thanh operated like most consultants:
- Client hires → he builds → it works → hands it over → engagement ends
- Another client comes with a nearly identical problem
- He builds it again. From scratch.

Concrete: Seth and Steve at Transwestern needed a morning call sheet (property data, occupancy, Google Maps, recent lease activity). Built it. Handed it over. A few months later, another brokerage came with basically the same workflow. He rebuilt it. "At some point I started asking: why do I keep giving this away?"

## The shift: keep the IP, license the access
Now when Thanh builds an agent for a client:
- He keeps the intellectual property
- The client gets access — not ownership
- They can use it; they can't resell it, reverse-engineer it, or hand it to a competitor
- When the engagement ends, the agent stays in Thanh's library

Contracts need IP retention clause, license terms, a non-compete (time-limited — usually 1–2 years — and industry-specific rather than blanket). Not complicated legal work; a good attorney can draft in an afternoon.

## How it works in practice
Lucas Siegel (co-founder of Yuna, AI mental health platform, 50K users, 155 countries, $30M valuation) asked whether Thanh would build him a sales prospecting agent — something similar to an investor-targeting pipeline already built.

Thanh's answer: "I might already have that built. You'd just license it from me." Pay per 100 introductions or a flat monthly fee. **No new build on his end.** Lucas gets something designed, tested, and refined in a real deployment.

> "Every client engagement is now an investment in a library rather than a one-time delivery. The first client pays for the full build — customized to their workflow, their data sources, their specific use case. I keep the IP. If the next client needs something similar, I'm adapting an existing agent, which takes a fraction of the original time."

## The compound effect
> "Custom consulting has a fixed ceiling. Every client costs the same amount of your time. You can't serve 10 clients as efficiently as you serve 1, because each one requires a full custom build from scratch."

> "The agent library breaks that relationship. Second client with a similar use case doesn't pay for a new build — they pay for access to what already exists. Third client, same thing. The marginal cost of serving each new client decreases as the library grows."

> "Think about it like the difference between a contractor and a software company. The contractor's revenue scales with hours worked. The software company's revenue scales with users — the build cost doesn't multiply with each new customer."

## The question worth asking
> "If you're doing any kind of implementation or consulting work right now — AI or otherwise — here's a question: after every engagement ends, what do you have left? If the answer is 'a good client relationship and a case study,' that's something. But you've also handed over the actual work product."
