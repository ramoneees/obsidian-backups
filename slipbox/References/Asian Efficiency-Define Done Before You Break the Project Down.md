# Define Done Before You Break the Project Down

**Fonte:** Asian Efficiency
**Data:** 3 de novembro de 2026
**URL original:** https://www.asianefficiency.com/goals/define-done-before-project-breakdown/
## Resumo

Projetos que nunca "chegam" costumam faltar com um Definition of Done: sem ele, quebrar em tarefas é andar em direção ao horizonte. A receita: escrever o estado final em 1–3 frases antes de abrir o task manager, com o teste de um terceiro — se outra pessoa precisaria adivinhar se o projeto terminou, ainda não há definição. Só depois, fazer a engenharia reversa dos passos.

## Ideias principais

- **Planejar em doc primeiro**: task manager transforma cada linha em promessa (culpa do to-do não feito); Google Doc ou Notion é fluido — riscar, reordenar, jogar fora não é fracasso. Migrar para o app só quando o plano assentar.
- **Who Not How para projetos novatos**: quem já fez isso antes? Contratar expert por minuto (Clarity.fm) ou usar ChatGPT como expert — prompt pronto no artigo: "Você é um expert que fez esse tipo de projeto centenas de vezes. Aqui está o projeto e meu Definition of Done: dê-me os passos, os riscos e as considerações que provavelmente estou perdendo."
- **"What would have to be true"**: perguntar o que precisaria ser verdade para os stakeholders aprovarem; todo ponto do plano precisa servir a essa decisão — é o filtro anti feature-dumping.
- **Retrospectiva de 30 minutos pós-projeto** (Kaizen): o que foi bem, o que não foi, o que melhorar — e o banco de dados resultante de forças/fraquezas do time alimenta alocação futura, até em projetos sem relação.
- Bônus do artigo: a câmera do app do ChatGPT para pesquisa rápida (rotulo de suplemento, tradução, identificação de objeto) — 30 minutos de pesquisa manual economizados.
